# CorpAI Board Decision

Date: 2026-04-12

## Decision

CorpAI should be run as `CorpAI AgentOps`: the control plane for governed AI agent execution across `Codex CLI`, `Gemini CLI`, `Claude Code`, `OpenRouter`, and direct APIs.

The company should not position itself as:

- a model vendor
- a generic AI dashboard
- a vague AI transformation platform
- a broad wrapper for every business workflow

The board consensus is that CorpAI becomes category-leading by proving one narrow but high-frequency technical workflow first, then expanding from that wedge.

## Category Sentence

`CorpAI is the control plane for governed AI agent execution.`

## Decide

- Sell governed execution, not raw model access
- Keep the wedge narrow: technical teams already using coding agents
- Treat the marketing site as the sales surface, not the product moat
- Build the moat in routing, approvals, audit logs, spend visibility, workflow packs, and reporting
- Start with one repeatable technical workflow that buyers immediately understand

## Do Next

### Next 30 Days

1. Close 3 paid `AgentOps Audit` engagements
2. Convert the best audit buyers into `Managed Pilot` customers
3. Make the funnel explicit:
   - homepage
   - buy page
   - demo
   - checkout
   - intake / confirmation
4. Build one stronger proof surface around `PR Review AgentOps`
5. Add a post-checkout success path and buyer intake flow

### Next 90 Days

1. Turn pilots into proof:
   - one quantified case study
   - one ROI calculator
   - one measurable pilot narrative
2. Harden the operating layer:
   - runtime routing
   - approval rules
   - usage reporting
   - workflow packs
   - billing / entitlement logic
3. Convert successful pilots into recurring `Hosted Control Plane` subscriptions
4. Add adjacent workflow packs only after the wedge converts:
   - bugfix
   - migration
   - incident triage

## Single Best Product To Build Next

`PR Review AgentOps`

Why:

- easy to understand
- high-frequency for technical teams
- naturally demonstrates routing and approvals
- produces measurable outcomes
- supports audit, pilot, and control-plane packaging

## Biggest Risks

- the category still being read as “wrapper” or “orchestration tool”
- the site outrunning the actual governed runtime
- demo polish without product depth
- too many audiences too early
- abstract language reducing urgency and pricing power

## Messaging Direction

Use:

- `Govern every AI agent run across your team.`
- `CorpAI is the control plane for Codex CLI, Gemini CLI, Claude Code, OpenRouter, and direct APIs.`
- `One policy layer. One routing layer. One approval layer. One reporting layer.`

Avoid:

- `AI magic`
- `fully autonomous`
- `replace your team`
- `AI operating system` as the front-door category label
- broad automation claims outside the technical wedge

## Packaging Direction

- `AgentOps Audit`
- `Managed Pilot`
- `Hosted Control Plane`

Do not add more pricing tiers yet.

Do not move to seat pricing yet.

Price on:

- workflow scope
- repo count
- approval complexity
- support intensity
- governed run volume

## Stop Doing

- stop broadening the story into generic AI categories
- stop selling the runtime vendors as the product
- stop adding features outside the trust loop
- stop optimizing for novelty over buyer clarity

## Summary

CorpAI should win by becoming the default purchase for technical teams that already use coding agents and now need control, policy, approvals, and reporting. The next phase is not more category expansion. It is proof, pilots, and a stronger governed execution product loop.
