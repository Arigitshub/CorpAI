# CorpAI Required Docs

This is the minimum doc system CorpAI should maintain while turning the project into a sellable AI workflow business.

## Strategy

- `docs/OPERATOR_STRATEGY.md` - category, ICP, offer strategy, and execution plan
- `docs/BOARD_MEETING_BACKBONE_PLAN.md` - board-level business model, pricing, billing, and backbone direction
- `docs/CONTROL_PLANE_ARCHITECTURE.md` - canonical system layers and execution model
- `docs/CATEGORY_BRIEF.md` - category definition, positioning, market alternatives, and language rules
- `docs/ICP.md` - ideal customer profile, buyer roles, disqualifiers, and first-vertical constraints
- `docs/OFFER_ARCHITECTURE.md` - offer ladder, packaging, and scope boundaries
- `docs/PRICING_POLICY.md` - price floors, pricing variables, and discount rules

## GTM

- `docs/SALES_NARRATIVE.md` - pitch structure, homepage language, and buyer framing
- `docs/DEMO_SCRIPT.md` - exact flow for a live product demo
- `docs/ROI_MODEL.md` - baseline math, KPI definitions, and ROI calculator inputs
- `docs/CASE_STUDY_TEMPLATE.md` - template for pilot proof and renewal proof
- `docs/OBJECTION_HANDLING.md` - common objections and approved responses

## Delivery

- `docs/PILOT_PLAYBOOK.md` - how a pilot is scoped, launched, reviewed, and converted
- `docs/IMPLEMENTATION_CHECKLIST.md` - repeatable implementation sequence
- `docs/APPROVAL_POLICY.md` - human approval rules and exception routing
- `docs/WEEKLY_REVIEW_TEMPLATE.md` - recurring review format for buyers
- `docs/STARTER_PACK_CODING_AGENT_WORKFLOWS.md` - first workflow pack and starter configuration

## Product

- `docs/RUNTIME_CONTRACT.md` - normalized adapter execution contract for CLI and API runtimes
- `docs/PROVIDER_ROUTING_POLICY.md` - runtime selection, fallback, cost, and quota policy
- `docs/APPROVAL_ENGINE_SPEC.md` - approval states, thresholds, protected actions, and review flow
- `docs/WORKFLOW_PACK_SPEC.md` - first workflow-pack boundaries, logic, and outputs
- `docs/METRICS_DEFINITION.md` - exact metric definitions and formulas
- `docs/INTEGRATIONS_MAP.md` - systems, dependencies, and data flow
- `docs/ESCALATION_THRESHOLDS.md` - what gets automated, what gets escalated, and why
- `docs/BILLING_AND_PACKAGING.md` - Stripe, contracts, plan boundaries, and packaging rules

## Operations

- `docs/EXECUTION_BACKLOG.md` - current execution queue
- `docs/ROADMAP_NOTES.md` - roadmap reasoning and sequence notes
- `docs/WORKSPACE_LAYOUT.md` - canonical repo and folder layout

## Rule

If a feature, workflow, or GTM claim does not have a matching doc entry, it is not stable enough to become the default product story.
